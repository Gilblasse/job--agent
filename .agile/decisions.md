# Decisions

Recorded so they are not re-litigated. Rationale lives here; the trade-offs a reader meets
in the code are also noted at their site.

| # | Decision | Why |
|---|---|---|
| 1 | Python 3.11 | stdlib `sqlite3` satisfies "free local persistence" with no dependency; mature prompt and table libraries; user-selected. |
| 2 | Ports and adapters, pure domain | Makes the whole pipeline testable with no network, which is the only reason this was verifiable at all in an egress-blocked environment. Also makes the serverless path a swap rather than a rewrite. |
| 3 | Three gate outcomes, not two | Most postings omit pay, many omit workplace, remote postings often name no country. Collapsing "does not say" either hides jobs or misrepresents them. |
| 4 | Requirement-context detection over keyword matching | "Exclude CPA-required" must keep "CPA preferred" — otherwise the filter discards the jobs it was written to find. |
| 5 | Registry seeded from outscal/OpenJobs, filtered | With no cross-company search anywhere, an empty registry means an empty results table. 1,766 boards, 1,307 on P1 platforms. |
| 6 | Workday as P1 despite its cost | With aggregators out of scope, it is the only source covering onsite non-tech US metro roles. Accepting 20-per-page and a request per description is the price of that coverage. |
| 7 | Per-host rate limiting, not per company | Several platforms host thousands of tenants behind one name; per-tenant limiting would 429-storm them. |
| 8 | Blocked is per-run, never permanent | A shared host that throttles today must not be struck off forever. |
| 9 | Rate-limited tracked separately from gone | The boards most worth reading are the likeliest to throttle; conflating them rots the registry. |
| 10 | Identical titles at one employer and location collapse | Splitting needs a requisition id most sources do not publish; showing the same job twice is worse. |
| 11 | "Manager" is not a seniority level | Rank in "Engineering Manager", job family in "Project Manager". Reading it as rank silently deletes a whole profession; not reading it as rank shows a few roles the user can exclude by title. The recoverable error wins. |
| 12 | Named locations are a hard gate | A search for Dallas returning San Francisco is a wrong answer, not a ranking flaw. Remote roles are exempt when remote is acceptable. |
| 13 | Inflection-tolerant phrase matching, final word only, 5+ characters | Excluding "auditing" must catch "audit"; stemming "plus" to "plu" would match "plush". |
| 14 | Fixtures from documented schemas, clearly labelled | No live capture was possible. Labelling them is the difference between a limitation and a misrepresentation. |
| 15 | SmartRecruiters and Workable held at P2 | Unresolved robots.txt conflicts. Shipping them would contradict the legitimate-access constraint on an unverified assumption. **Resolved 2026-09-15 by reading both files live: see 27 and 28.** |
| 16 | Registry growth via the Common Crawl index, not a search API | Every free whole-web search API is gone: Bing Search retired, Google CSE closed to new signups and ending, the rest paid or aggregator-backed. Common Crawl is free, keyless, non-profit, and exists to be queried programmatically — so it satisfies "free forever" and "legitimate access" together. |
| 17 | Common Crawl is the only route to Workday tenants | Each tenant is its own hostname and the (tenant, instance, site) triple is not guessable from a company name, so no `site:` query on any engine can enumerate them. A subdomain wildcard on the index can. That is the exact gap in coverage: onsite, non-tech, US. |
| 18 | Sweeps are bounded, paced and resumable | The index is volunteer-funded. One request per second, a page budget per run, and a saved cursor make discovery a background chore rather than a load spike on somebody else's free service. |
| 19 | A sweep that stops early is never recorded complete | Parking the cursor as finished after an error leaves the rest of the pattern unread for the life of the crawl — a silent hole in reach, which is the one thing the registry cannot afford. |
| 20 | Discovered boards carry no US signal | An index entry proves a board exists, not where it hires. Marking it US would push it ahead of boards with real evidence in the fan-out order. |
| 21 | Wanted titles match the title only; responsibilities match the duties section | Live: a marketing role matched an accounting search on "liaise with our accountant", and a sales role at an AP-software vendor matched on its product blurb. A phrase in the company pitch is evidence about the company, not the job. |
| 22 | No title match plus no description is a FAIL, not UNVERIFIABLE | The title is always present and always reaches a verdict; unverifiable is for when no branch can. Saying unverifiable put twenty over-budget Workday postings -- software, sales, ML -- into an accounting search as flags. |
| 23 | Barred responsibilities are scoped like wanted ones; keywords and deal-breakers stay posting-wide | Symmetry with 21, and a live false negative: an AP manager rejected on "audit trail" in a requirements list. Keywords and deal-breakers are meant to fire on any mention, so they are left alone. |
| 24 | Country detection uses a full place vocabulary, compiled once | Sixty hand-picked names missed "Croatia". Every ISO country, major regions and ~330 cities, as one longest-first pattern per vocabulary, because per-name patterns at that size cost minutes per run. Ambiguous two-letter prefixes with an unrecognised city stay unknown rather than guessed. |
| 25 | Skills are matched as names: no inflection, and with the user's casing | Live: "React" as a required skill matched a trading role on "react to volatility shifts". A lower-case skill in the spec still matches case-insensitively, so the user's own casing decides and nobody who did not ask is affected. |
| 26 | Common Crawl discovery is held, not shipped | Both `index.commoncrawl.org` and `data.commoncrawl.org` publish `Disallow: /`. The documented query API is almost certainly not the target, but the tool honours the file rather than the guess -- the same posture as decision 15. Reversible on an explicit statement from Common Crawl. |
| 27 | Workable ships, through the widget API on `apply.workable.com` | Its robots.txt, read live 2026-09-15, disallows nothing; `www.workable.com` disallows only account paths and redirects the API to the apply host anyway. The "429s at fan-out scale" rumour did not reproduce: all 172 seeded boards in 43 s at the standard per-host pace, no throttling. Multi-city jobs are folded into one posting because the widget repeats them once per city under one shortcode. |
| 28 | SmartRecruiters stays unread, now on evidence rather than rumour | `api.smartrecruiters.com/robots.txt` says `Disallow: /` for every agent and carves out `/v1/companies/` for `LinkedInBot` alone. A named exception makes the general refusal a decision, not an oversight. Its 287 boards stay seeded so the split is visible, and stay unread. |
| 29 | `parse_location` structures the first of several semicolon-separated places | A folded location ("Dallas, Texas, United States; New York, New York, United States") scanned whole found whichever state sorts first alphabetically and took everything before it as the city. The raw string still carries every place, which is what the location gate reads. |
| 30 | The post-run "New matches" table is scoped to that run | Live, a heading that counted two new matches sat over three rows: the unscoped query listed every job whose latest verdict was still flagged new, including one first seen two runs earlier on a board the current run never reached. The heading and the rows must describe the same run. |
| 31 | The robots.txt read is not charged to a source's board allowance | The planner hands a source exactly `budget` boards; charging the one robots read against that allowance meant the last board was never reached, on every platform, every run, and the coverage table said "1 more not reached within this run's budget" each time. It is still counted as traffic and still paced. |
| 32 | Phrases split on hyphens as well as spaces, and words may be joined by nothing | A user typed "Front-end developer" and had to also type "Front End Developer" and "Frontend Developer" to cover the market. Now any of the first two spellings finds all three. The closed form typed still matches only itself: nothing says where it divides. |
| 33 | The wizard confirms entries of three characters or fewer in prose-scanned lists | A live wizard session put a one-letter and a two-letter language into "duties you do not want", where either matches ordinary English on a single hit and silently deletes good jobs. One checkbox per list; unticked entries are rewritten or dropped. Lists read in context (credentials, companies, places) are not interrupted, because "RN" is a name. |
| 34 | The wizard's preview describes each gate lazily, one description per gate | Every description was an f-string in one dict literal, evaluated for every gate; the workplace line's `.value` ran against the country gate's strings and crashed the wizard after the last question and before saving. Also: every prompt now names its scope (TITLE, DUTIES, ANYWHERE), because that is the difference between a filter and a deal-breaker. |
| 35 | A run reports progress in two phases: boards and postings during fan-out, matches during evaluation | Cross-source dedup needs every posting before a canonical record exists; judging per source would double the gate work or produce a count that falls after the merge. The user accepted this deviation in plan review. Display hooks are guarded so a display bug never reads as a source failure, and results are gathered in plan order so job ids and the coverage table are stable whatever the completion order. |
| 36 | Dismissal is its own user status, and the reason is stored verbatim with the rule the user chose | `results --rejected` already means gate-rejected; the user's action must never share that word. There is no model to interpret the reason, so the user picks the rule (employer, title wording, duty, skill, phrase anywhere, seniority, or just hide); `record_match` never overwrites a status, so a dismissed job that matches again stays hidden, and a GONE verification preserves it. |
| 37 | The results table leads with the job id and ends with the link | The `#` column was a row number while `show`, `mark` and `dismiss` take the id. Links are a column by the user's choice, folded rather than truncated so they stay copyable; `--no-links` for narrow terminals. |
| 38 | A title's location suffix is found from the right | The regex matched the leftmost separator, so "Front-End Developer, Austin TX" became "front" for identity and every "Front-..." role at one employer and place collapsed. Found while building `title_core`; the fix is shared with `normalize_title`. |
| 39 | The cloud database is Turso over Hrana HTTP, driven by `infra/turso.py` | Free forever (5 GB, 10M row writes/mo, no card); libSQL is SQLite, so `Store`'s SQL runs unchanged. Neon and Supabase free tiers cap at 0.5 GB, below the 638 MB the local database reached after ten live runs. pyturso is alpha and libsql replica sync moves 4 KB pages, which a run's 20k `last_seen` touches would turn into ~150 MB per run. |
| 40 | The runner is GitHub Actions and keeps no state | A run takes minutes at a polite per-host pace and must be the only runner; Vercel Hobby caps a function at 300 s. A stateless runner pulls the searches and registry, runs the unchanged engine locally and publishes in atomic batches keyed by search uid and job identity. |
| 41 | Every publish batch carries the lease guard, and takeover invalidates the previous owner atomically | A CHECK-constrained row written first in every batch turns "lost the lease" into a failed statement, so the batch rolls back. Taking the lease overwrites the single lease row's token and closes the old owner's request in one transaction; the old runner's heartbeat, guards and finish then match nothing. Reconciliation is display only. |
| 42 | At most one queued request, by a partial unique index, and a workflow with no inputs | Two simultaneous clicks cannot both dispatch; the second attaches. GitHub replaces an older pending workflow with a newer one, so the workflow carries no work of its own: every run consumes what the database has queued. |
| 43 | The search screen shows one completed run, with the card and ordering fields frozen on the verdict | The historical "latest verdict per job" query changes under a reader as runs complete and as jobs are rewritten; a pinned run with frozen fields and an `m.id` tie-breaker cannot move between pages. The historical view remains for the CLI. |
| 44 | A search's latest three completed runs are available; older ones answer `410 expired` | Retention must not touch a run someone may still be reading, and a partially pruned run must never be served as if whole. |
| 45 | The posting body is current text; the detail says when the evaluated version differed | Snapshotting every body per run is the write budget; the verdict's content hash against the job's says whether the reasons still describe the text on screen. A `job_versions` table keyed by hash is the upgrade if readers need the evaluated text. |
| 46 | Searches carry a uuid identity and a revision | SQLite reuses row ids, so a deleted-and-recreated search could receive an old run's results; `uid` cannot be reused. Every edit bumps `revision`; an update or dismissal with a stale revision is refused rather than silently overwriting another tab. |
| 47 | `last_seen` has day granularity, decided per job and per source URL | An unchanged posting seen twice in a day costs no write; a new URL for an unchanged job is still inserted; each URL's timestamp moves on its own. Change is detected by a content hash over the columns the update writes. |
| 48 | Rejected verdicts are pruned only outside the available window and only for jobs re-encountered in a newer run | A job matched in run A, rejected in B and absent from C keeps B's rejection as its latest verdict; pruning it would resurface A's match in the historical view. Match verdicts are never pruned. |
| 49 | Jobs unseen for 60 days are removed unless saved, applied, dismissed, fed back on, or shown by an available run | The only runner-side delete, guarded exactly so; storage stays bounded without cascading over anything the user touched. |
| 50 | Vite + React for the web app, by the user's choice; the API is FastAPI on Vercel behind one shared password | The user chose the conventional toolchain over a no-build page. A router dependency, not middleware, checks the password so the static build stays on the CDN. An unconfigured password fails closed. |
| 51 | The verdict table is indexed job-first, and the two statements that walk it say `INDEXED BY` | On 194k rows the planner served the retention query's EXISTS from `(search_id, run_id)`, ~58k rows per candidate, and one chunk outlasted the lease; `(job_id, search_id, run_id)` makes it a few rows and also serves "seen before" and the publish `NOT EXISTS`. The hint is deliberate: a plan that only happens to be right is one statistics refresh away from wrong, and this one held a shared lock for 25 minutes. |
